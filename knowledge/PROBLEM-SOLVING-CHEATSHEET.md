# LeetCode 陌生题解题 Cheatsheet

> 目标：面对一道没见过的题，不靠猜题型，也能在 10–15 分钟内得到一个可解释、可验证的解题方向。

## 一句话总纲

```text
读懂输入输出 → 用小例子澄清 → 写出暴力 → 找重复工作/无效枚举
→ 用数据结构或单调性消掉瓶颈 → 写清不变量 → 再写代码
```

不要从“这题像什么模板”开始。先问：**暴力在重复做什么？哪条信息能让我不再重复？**

---

## 0. 先判断时间预算

令 `n` 为主要输入规模。下面只是量级直觉，不是绝对规则：

| `n` 的量级 | 优先考虑的复杂度 |
| --- | --- |
| `n <= 20` | `O(2^n)`、回溯、状态压缩 |
| `n <= 100` | `O(n^3)` 有时可行 |
| `n <= 1,000` | 通常瞄准 `O(n^2)` |
| `n <= 100,000` | 通常需要 `O(n log n)` 或 `O(n)` |
| `n >= 1,000,000` | 通常需要接近 `O(n)` |

如果输入有两个独立维度，算乘积：`m * n`。如果是图，复杂度通常用 `V + E` 表示。

## 1. 前两分钟：把题目翻译成自己的话

在纸上或注释里补完这五句：

```text
输入是：________。
输出是：________。
我要找的是：值 / 下标 / 个数 / 是否存在 / 所有方案 / 最优方案。
允许我改变输入吗：是 / 否。
最容易漏掉的边界是：空、单元素、重复、负数、溢出、无解、全部满足。
```

然后手推一个最小例子和一个反例。例子不是为了“感觉正确”，而是为了回答：

- 候选答案是什么？
- 哪些候选能被提前淘汰？
- 状态变化发生在什么时候？
- 相等、重复、越界时怎么办？

如果还说不清输入和输出，不要急着选算法。

---

## 2. 第一个真正的问题：暴力怎么做？

先写一句不考虑效率的方案：

```text
我会枚举 ______，对每个候选再检查 ______，所以复杂度是 ______。
```

常见暴力结构：

- 枚举每对元素：`O(n^2)`。
- 枚举每个子数组，再重新统计：`O(n^2)` 或 `O(n^3)`。
- 对每个位置向左/右重新搜索：`O(n^2)`。
- 枚举所有选择：`O(2^n)` 或 `O(n!)`。
- 对每次查询重新扫描整个区间：`O(nq)`。

然后圈出最贵的那一层：**它重复计算了什么？** 这通常直接指向优化机制。

| 暴力的重复工作 | 优先尝试的消除机制 |
| --- | --- |
| 反复查某个值是否出现、出现几次、上次在哪 | 哈希表 / 集合 |
| 反复计算连续区间的和或频次 | 前缀和 / 滑动窗口 |
| 反复搜索有序空间 | 二分查找 |
| 反复寻找左/右第一个更大或更小元素 | 单调栈 |
| 反复寻找当前最小/最大候选 | 堆 / 单调队列 |
| 递归反复求相同参数的结果 | 记忆化 / 动态规划 |
| 重复遍历相连节点 | DFS / BFS + visited |
| 反复判断两个点是否属于同一集合 | 并查集 |
| 多次修改区间内每个元素 | 差分数组 |

## 3. 解题路由：先问结构，再选模式

按顺序问，命中后仍要解释它消掉了哪部分暴力。

### A. 答案是否涉及连续的一段？

如果是子数组、子串或连续区间：

1. 窗口右移时，旧信息能否通过“加入右端、移除左端”维护？
   - 能，而且合法性随窗口缩放有方向性：**滑动窗口**。
   - 固定长度：定长窗口。
   - 求最长且要求“至多/不超过”：右扩、违规时左缩。
   - 求最短且满足“至少”：右扩到满足，再尽量左缩。
2. 目标能否写成 `prefix[r] - prefix[l]`？
   - 区间和查询：**前缀和**。
   - 要找和为 `k` 的区间：**前缀和 + 哈希表**。
   - 多次区间增减：**差分数组**。
3. 元素可能为负数吗？
   - 如果会破坏“右扩只会变大、左缩只会变小”的单调性，普通滑动窗口通常不适用；转看前缀和、单调队列等。

### B. 输入是否有序，或答案是否具有单调可行性？

- 在有序数组中查值或左右边界：**二分查找**。
- 问“最小的可行值”或“最大的可行值”，且 `check(x)` 呈现 `False...True` 或 `True...False`：**答案二分**。
- 有序数组里寻找一对值，移动一端能确定排除一批答案：**对撞双指针**。

二分前必须写出：

```text
搜索空间是 ______。
check(x) 的含义是 ______。
单调性是 ______。
我要找第一个 True / 最后一个 True。
```

### C. 是否需要快速回答“见过没有、出现几次、对应谁”？

- 值到次数、位置、分组的映射：**哈希表**。
- 只关心是否存在或去重：**集合**。
- 值域与下标一一对应，且要求 `O(1)` 额外空间：**下标归位 / 原地标记**。
- 允许排序且不需要保留原下标：先问排序能否换来相邻性或单调性。

哈希不是答案本身。要说清表中保存的是“扫描过的前缀里，未来查询需要的最小信息”。

### D. 是否在维护一批“还没结算”的候选？

- 最近的未闭合结构，如括号：**普通栈**。
- 找左/右第一个更大或更小：**单调栈**。
- 滑动窗口内持续取最大/最小：**单调队列**。
- 动态保留 Top K：维护大小为 `k` 的**堆**。
- 多个有序来源，每次取最小头部：**堆做多路合并**。

关键问题：一个候选被弹出时，为什么它以后永远不可能更优？

### E. 输入是链表、树、图，还是矩阵？

**链表**

- 倒数第 `k` 个：固定间距双指针。
- 环、中点：快慢指针。
- 改连接：先保存 `next`，再重连；考虑 dummy node。
- 合并多个有序链表：分治或堆。

**树**

- 先定义递归函数：参数向下携带什么？返回值向上汇报什么？
- 子树结果合并：通常是后序 DFS。
- 最短层数或逐层处理：BFS。
- 根到当前节点的状态：进入时加入，离开时撤销。
- BST：优先寻找中序有序性或上下界约束。

**图 / 网格**

- 找可达区域、连通分量：DFS/BFS + visited。
- 多个起点同时向外、求等权最短时间：多源 BFS。
- 有向依赖、课程顺序、判断依赖环：拓扑排序。
- 动态合并并查询连通性：并查集。
- 非负边权最短路：Dijkstra；普通 BFS 只保证等权最短路。

**矩阵**

- 如果核心是可达性，把格子当图。
- 如果核心是按方向走、旋转、边界收缩，才是矩阵模拟。

### F. 是否要枚举所有选择或求全局最优？

先区分目标：

- 要输出所有组合、排列、路径：**回溯**。
- 只求最优值、可行性或方案数，且子问题重复：**动态规划**。
- 每一步能证明某个局部选择不会损失最优解：**贪心**。

**回溯四件套**

```text
路径是什么？候选有哪些？什么时候结束？选择后如何撤销？
```

**DP 四件套**

```text
状态定义：dp[...] 表示什么？
转移：它依赖哪些更小状态？
初始值：最小问题的答案是什么？不可达如何表示？
顺序：为什么依赖项会先算好？
```

如果无法用一句完整的话定义 `dp[state]`，先不要写状态转移。

**贪心证明**

不要因为“看起来每次取最大的”就写贪心。至少要有一种理由：

- 交换论证：任意最优解都能换成当前选择而不变差。
- 支配关系：被丢弃状态未来不可能胜过保留状态。
- 单调边界：只需要保留目前最远、最小或最大的有效边界。

## 4. 不是关键词匹配：容易误判的边界

| 表面特征 | 不一定是 | 真正判断标准 |
| --- | --- | --- |
| 代码有两个指针 | 双指针 | 移动一端是否能安全淘汰一批候选？ |
| 题目有连续区间 | 滑动窗口 | 窗口合法性是否能增量维护，并随缩放单调变化？ |
| 输入是矩阵 | 矩阵模拟 | 核心是方向/边界，还是图的可达性？ |
| 用了 priority queue | 堆题 | 堆是否是降低复杂度的核心机制？ |
| 求最大/最小 | 动态规划 | 是否存在重复子问题和可复用状态？能否贪心或二分答案？ |
| 有重复计算 | DP | 重复子问题是否能由少量状态完整描述？ |
| 有环 | 并查集 | 是无向连通性，还是有向依赖环？后者常用拓扑/DFS。 |

## 5. 写代码前：强制写出不变量

不变量是“循环或递归进行到任意时刻都为真”的一句话。常见写法：

```text
哈希：seen 保存下标 i 之前所有元素的 ______。
窗口：窗口 [left, right] 始终满足 ______；left 之前的起点已被证明无效。
双指针：答案只可能留在区间 [left, right] 内。
二分：目标边界始终位于搜索区间 ______ 内。
单调栈：栈内下标对应的值保持 ______，且都还没找到 ______。
BFS：队列中的节点按距离 ______ 的顺序等待处理。
DFS：dfs(node) 返回 ______，并假设子树答案已经正确。
DP：dp[state] 等于 ______，其依赖状态已经计算完。
```

如果说不出不变量，通常意味着：

- 还没理解为什么某个指针可以移动；
- 状态中缺少未来需要的信息；
- 数据结构存了太多或太少；
- 正在套模板，而不是推导。

### 5.1 每个主要模式的不变量例子

下面的重点不是记题目答案，而是练习句式：**任意时刻什么为真，因此哪一步操作是安全的。**

#### 数组与哈希

**哈希查询——Two Sum**

```text
不变量：处理 nums[i] 前，seen 恰好保存下标小于 i 的元素值及其下标。
因此：如果 target - nums[i] 在 seen 中，找到的是两个不同元素；否则处理完 i 后再写入 seen。
```

**计数哈希——Group Anagrams**

```text
不变量：哈希表的每个 key 是唯一的字符频次签名，value 包含扫描前缀中所有具有该签名的字符串。
因此：新字符串只需计算一次签名，就能进入且只进入正确的组。
```

**下标归位——First Missing Positive**

```text
不变量：值 x 的目标位置固定为 x - 1；每次交换至少把一个合法值放入其目标位置。
因此：交换总次数是 O(n)；结束后第一个 nums[i] != i + 1 的位置就是缺失值。
```

**前后缀聚合——Product of Array Except Self**

```text
不变量：第一次扫描后 ans[i] 是 i 左侧所有元素的乘积；反向扫描到 i 时，right 是 i 右侧所有元素的乘积。
因此：ans[i] *= right 严格排除了 nums[i] 本身。
```

#### 双指针

**同向压缩——Move Zeroes**

```text
不变量：[0, slow) 是保持原相对顺序的非零元素，[slow, fast) 是已处理但待填充区域，[fast, n) 尚未处理。
因此：fast 遇到非零值时放到 slow，并让 slow 前进，不会覆盖任何未处理元素。
```

**有序对撞——Two Sum II**

```text
不变量：所有仍可能组成 target 的配对都位于 [left, right] 中。
因此：当前和过小时，固定 left 与任何更小/相同右端都不可能命中，可以安全 left += 1；过大时同理收 right。
```

**支配淘汰——Container With Most Water**

```text
不变量：被跳过端点参与的所有剩余配对，都不可能超过已经检查过的最好答案。
因此：移动较矮端是安全的；保留它只会让宽度变小，而高度上限仍被它限制。
```

#### 滑动窗口

**变长求最长——Longest Substring Without Repeating Characters**

```text
不变量：收缩结束后，[left, right] 内没有重复字符，并且对当前 right，left 是不产生重复所允许的最左位置。
因此：此时 right - left + 1 是以 right 结尾的最长合法窗口。
```

**变长求最短——Minimum Size Subarray Sum（正数数组）**

```text
不变量：右端加入后，只要窗口和仍 >= target，就持续移动 left；每次移动前的窗口都是当前 right 下的一个可行候选。
因此：收缩结束时，当前 right 对应的最短可行窗口已经被检查，不会漏解。
```

**定长窗口——长度为 k 的最大和**

```text
不变量：更新答案时，window_sum 恰好等于最近 k 个元素之和。
因此：每次加入新右端并移除过期左端，即可用 O(1) 更新下一个窗口。
```

**至多 K 转恰好 K**

```text
不变量：atMost(K) 中，对固定 right，[left, right] 以及所有更晚的起点都是合法窗口，共 right - left + 1 个。
因此：atMost(K) - atMost(K - 1) 恰好删除少于 K 种的窗口，只留下恰好 K 种。
```

#### 前缀和与差分

**前缀和——Range Sum Query**

```text
不变量：prefix[i] 始终表示 nums[0:i]，也就是前 i 个元素之和。
因此：区间 [l, r] 的和等于 prefix[r + 1] - prefix[l]。
```

**前缀和 + 哈希——Subarray Sum Equals K**

```text
不变量：处理当前前缀和 cur 时，seen[x] 是此前出现过的前缀和 x 的次数。
因此：每个值为 cur - k 的旧前缀都唯一对应一个以当前位置结尾、和为 k 的子数组。
```

**前缀取模——Subarray Sums Divisible by K**

```text
不变量：seen[r] 保存此前前缀和模 k 等于 r 的次数。
因此：两个前缀余数相同，它们的差就能被 k 整除。
```

**差分数组——区间批量加**

```text
不变量：diff[i] 只记录值在位置 i 相对 i - 1 的变化量。
因此：[l, r] 加 v 只需在 l 开始 +v、在 r + 1 结束 -v；最终一次前缀累加即可恢复所有位置。
```

#### 二分查找

**边界二分——第一个大于等于 target 的位置**

```text
不变量：使用半开搜索区间 [lo, hi)；lo 左侧都 < target，hi 及其右侧都 >= target，真正边界始终夹在 lo 与 hi 之间。
因此：a[mid] >= target 时 mid 仍可能是第一个，令 hi = mid；否则 mid 必不可能，令 lo = mid + 1。
```

**答案二分——Koko Eating Bananas**

```text
不变量：速度小于 lo 的都已证明不可行，速度大于等于 hi 的候选区间包含当前最小可行答案。
因此：mid 可行时保留 mid 并向左找；不可行时排除 mid 及其左侧。
```

**旋转数组二分——Search in Rotated Sorted Array**

```text
不变量：目标若存在，一直保留在 [lo, hi]；每轮至少有一半是正常升序区间。
因此：先判断哪半有序，再判断 target 是否落在其值域内，可以安全排除另一半。
```

#### 栈与单调结构

**普通栈——Valid Parentheses**

```text
不变量：栈从底到顶保存所有尚未匹配的左括号，栈顶是下一个右括号唯一允许匹配的对象。
因此：右括号与栈顶不匹配时可以立即判错。
```

**表达式栈——Evaluate Reverse Polish Notation**

```text
不变量：栈保存已扫描前缀中尚未被运算符合并的完整操作数。
因此：遇到二元运算符时，栈顶两个数就是它的右、左操作数，合并结果再入栈。
```

**辅助极值栈——Min Stack**

```text
不变量：每一层同时保存该值入栈后，栈前缀的最小值。
因此：push/pop 后栈顶附带的最小值始终是当前全栈最小值。
```

**单调栈——Daily Temperatures**

```text
不变量：栈内下标对应的温度单调不增，且这些天都还没找到右侧第一个更高温度。
因此：当前温度更高时，被弹出的每一天第一次遇到更高温度，距离可以当场确定。
```

**单调队列——Sliding Window Maximum**

```text
不变量：队列中的下标从队首到队尾递增，对应值单调递减；队首始终是当前窗口最大值。
因此：新值进入时，队尾所有不大于它的元素永远不可能再成为最大值，可以永久弹出；过期下标从队首移除。
```

#### 堆

**Top K——Kth Largest Element**

```text
不变量：扫描任意前缀后，大小不超过 k 的小根堆保存该前缀最大的 k 个元素，堆顶是其中最小者。
因此：扫描结束时堆顶就是全局第 k 大。
```

**多路合并——Merge K Sorted Lists**

```text
不变量：堆中每条未耗尽链表至多有一个当前头节点；堆顶是所有尚未输出元素中的全局最小值。
因此：弹出堆顶后只需把它所属链表的下一个节点加入堆。
```

**双堆——Median from Data Stream**

```text
不变量：lower 中每个值 <= upper 中每个值，且两堆大小差不超过 1。
因此：中位数总能由一个堆顶或两个堆顶的平均值得到。
```

#### 链表

**固定间距——Remove Nth Node From End**

```text
不变量：从 dummy 出发，fast 始终比 slow 超前 n + 1 个节点。
因此：fast 到 None 时，slow 恰好在待删除节点的前驱。
```

**快慢指针——Linked List Cycle**

```text
不变量：slow 每轮走一步，fast 每轮走两步；若进入同一个环，两者的环内相对距离每轮缩短一步（模环长）。
因此：有环必相遇；fast 到 None 则无环。
```

**原地反转——Reverse Linked List**

```text
不变量：prev 是已经反转好的前缀链表头，cur 是尚未处理后缀的头，二者合起来覆盖原链表且不丢节点。
因此：先保存 nxt，再令 cur.next = prev，便能安全扩大已反转前缀。
```

**有序合并——Merge Two Sorted Lists**

```text
不变量：dummy 到 tail 是已经确定的全局最小前缀，两个当前指针分别指向各自未处理部分的最小值。
因此：连接较小的当前节点不会错过更小候选。
```

#### 树

**后序 DFS——Maximum Depth**

```text
不变量：dfs(node) 返回以 node 为根的子树最大深度；调用者可假设左右子树返回值已经正确。
因此：当前结果就是 1 + max(left_depth, right_depth)。
```

**路径状态——Path Sum**

```text
不变量：进入 node 时，path_sum/path 恰好描述从根到当前节点的路径；离开 node 前撤销当前节点。
因此：兄弟分支不会看到彼此的路径状态。
```

**层序 BFS——Binary Tree Level Order Traversal**

```text
不变量：每一轮开始时，队列恰好包含当前层的全部节点。
因此：固定读取本轮队列长度，就能把这一层与下一层严格分开。
```

**BST——Validate Binary Search Tree**

```text
不变量：dfs(node, low, high) 中，node 的整个子树都必须落在祖先传下来的开区间 (low, high) 内。
因此：左子树上界收紧为 node.val，右子树下界收紧为 node.val。
```

**DFS/BFS 连通性——Number of Islands**

```text
不变量：visited 中的格子已经被发现且不会再次展开；一次搜索覆盖且只覆盖当前起点所在的连通分量。
因此：每从一个未访问陆地开始搜索，岛屿数恰好增加 1。
```

**无权最短路 BFS**

```text
不变量：队列按距起点非递减的距离处理节点；节点第一次被发现时得到的就是最短距离。
因此：应在入队时标记 visited，避免同层重复入队。
```

**多源 BFS——Rotting Oranges**

```text
不变量：初始队列含所有距离为 0 的源点；第 t 轮队列含所有将在时刻 t 扩散的节点。
因此：第一次到达某格的层数就是它到最近源点的最短距离。
```

**拓扑排序——Course Schedule**

```text
不变量：indegree[v] 是 v 尚未被移除的前置条件数；队列中只有当前入度为 0 的节点。
因此：弹出节点并删除其出边后，新变成 0 的节点才可安全加入顺序。
```

**并查集——Redundant Connection**

```text
不变量：find(x) 返回 x 当前连通分量的唯一代表元；find(a) == find(b) 当且仅当两点已连通。
因此：加入一条边前两端已有相同代表元时，这条边必形成环。
```

**Dijkstra——非负边权最短路**

```text
不变量：从小根堆弹出的、与 dist 一致的最小距离已经最终确定；堆中其余路径不会产生更短的回头路。
因此：可以用该节点松弛邻边；这个结论依赖所有边权非负。
```

#### 回溯

**排列——Permutations**

```text
不变量：进入 dfs 时，path 是一个无重复元素的合法排列前缀，used 准确标记其中已选择的元素。
因此：选择一个未使用元素、递归、再撤销，能让所有排列各出现一次。
```

**组合——Combinations**

```text
不变量：path 严格按下标递增，start 之前的候选在当前分支已永久跳过。
因此：下一层只从 start 之后选择，既不会重复组合，也不会遗漏。
```

**棋盘搜索——Word Search**

```text
不变量：递归位置 (r, c, i) 表示当前路径已匹配 word[0:i+1]，路径内格子被临时标记且没有重复使用。
因此：返回父层前恢复格子，其他路径仍可使用它。
```

#### 动态规划

**一维 DP——Climbing Stairs**

```text
不变量：dp[i] 是到达第 i 阶的方案数；计算 i 时，dp[i-1] 与 dp[i-2] 已经正确。
因此：最后一步只能从前一阶或前两阶到达，dp[i] = dp[i-1] + dp[i-2]。
```

**0/1 背包——Partition Equal Subset Sum**

```text
不变量：处理前 i 个数后，dp[s] 表示能否从这些数中选出和 s；每个数最多使用一次。
因此：容量必须倒序更新，确保本轮读取的是加入当前数之前的旧状态。
```

**网格 DP——Unique Paths**

```text
不变量：处理到格子 (r, c) 时，dp[c] 在更新前代表上方路径数，dp[c-1] 代表左方路径数。
因此：dp[c] += dp[c-1] 得到当前格子的路径数。
```

**双序列 DP——Longest Common Subsequence**

```text
不变量：dp[i][j] 是 text1 前 i 个字符与 text2 前 j 个字符的最长公共子序列长度。
因此：末字符相等时接在 dp[i-1][j-1] 后；不等时舍弃一个末字符取两者最大值。
```

**状态机 DP——股票含冷冻期**

```text
不变量：每天结束后，hold/sold/rest 分别是处于持有、当天卖出、非持有且可买状态的最大利润。
因此：每次转移只从前一天合法进入该状态的状态集合取最大值。
```

**区间 DP——Longest Palindromic Subsequence**

```text
不变量：dp[l][r] 是闭区间 [l, r] 内的最优答案；计算它时，更短区间已经正确。
因此：必须按区间长度递增，或让 l 逆序、r 正序计算。
```

#### 贪心与区间

**最远边界——Jump Game**

```text
不变量：扫描到 i 前，farthest 是所有已可达位置能延伸到的最远下标；[0, farthest] 全部可达。
因此：若 i > farthest 则不可能继续，否则用 i + nums[i] 扩大边界。
```

**局部贡献——Maximum Subarray**

```text
不变量：current 是以当前位置结尾的最大子数组和。
因此：若此前累积为负，它只会拖累任何包含当前值的后缀，可以安全从当前值重新开始。
```

**区间合并——Merge Intervals**

```text
不变量：按起点排序后，结果中除最后一个区间外都已永久封口；最后一个是扫描前缀唯一可能继续延伸的区间。
因此：新区间只需和结果最后一个比较。
```

**区间调度——最多不重叠区间**

```text
不变量：在已扫描候选中，保留的方案拥有相同数量下尽可能早的结束时间。
因此：选择最早结束的可行区间给未来留下最大空间，不会比任何更晚结束的选择差。
```

**扫描线——Meeting Rooms II**

```text
不变量：扫描到时间 t 时，active 等于已经开始但尚未结束的会议数。
因此：开始事件令 active +1，结束事件令 active -1，历史最大值就是所需房间数。
```

#### Trie 与字符串匹配

**Trie——Implement Trie**

```text
不变量：从根沿字符路径走到的节点，唯一代表已经读取的前缀；is_end 区分完整单词与普通前缀。
因此：某条字符边不存在时，该前缀及其所有扩展都不存在。
```

**KMP——子串搜索**

```text
不变量：扫描文本到当前位置时，j 是文本当前后缀与模式前缀匹配的最长长度。
因此：失配时可跳到 failure[j-1] 继续，不必重新比较已经证明相等的部分。
```

**滚动哈希——固定长度子串匹配**

```text
不变量：hash 始终对应当前长度固定的窗口内容。
因此：移除左字符、乘进制并加入右字符可 O(1) 得到下一窗口哈希；哈希相等仍需考虑碰撞。
```

#### 矩阵、位运算与设计题

**边界模拟——Spiral Matrix**

```text
不变量：top、bottom、left、right 始终包围所有尚未输出的格子，边界外都已按螺旋顺序处理。
因此：走完一条边后收缩对应边界；再次走底边/左边前要检查边界是否仍有效。
```

**同步状态——Game of Life**

```text
不变量：更新任意格子时，仍能读取所有邻居的旧状态；新状态不会污染后续判断。
因此：使用副本或编码同时保存旧、新两种状态，最后统一解码。
```

**XOR——Single Number**

```text
不变量：扫描前缀后的 xor 等于该前缀中所有出现奇数次元素的异或结果。
因此：成对元素利用 x ^ x = 0 消掉，最后只剩唯一元素。
```

**快速幂——Pow(x, n)**

```text
不变量：answer * base^exponent 始终等于原始目标 x^n。
因此：exponent 为奇数时把一个 base 乘入 answer；随后 base 平方、exponent 减半仍保持等式。
```

**数据结构设计——LRU Cache**

```text
不变量：哈希表中的每个 key 唯一对应双向链表中的一个节点；链表顺序准确表示从最近使用到最久未使用。
因此：get/put 必须同步更新两种结构，淘汰链表尾节点时也必须从哈希表删除。
```

### 5.2 从不变量反推代码结构

不变量不是写完代码后补上的解释。更实用的方法是先决定：

```text
1. 在哪个时刻，我希望什么性质成立？
2. 新元素或新状态会怎样破坏它？
3. 要先执行哪些修复动作，才能恢复它？
```

代码的执行顺序通常就是：

```text
接收新信息 → 修复不变量 → 使用不变量得到答案 → 进入下一轮
```

#### 1. 哈希表：先查询还是先写入？

以 Two Sum 为例，先决定：

```text
不变量：处理 nums[i] 时，seen 只包含 i 之前的元素。
```

为了保持“不包含当前元素”，代码只能先查询、后写入：

```python
for i, x in enumerate(nums):
    if target - x in seen:
        return seen[target - x], i
    seen[x] = i
```

如果先写入，当前元素就可能与自己配对。不变量直接决定了两行代码的先后顺序。

#### 2. 同向双指针：什么时候移动 slow？

以 Move Zeroes 为例，先决定：

```text
不变量：[0, slow) 始终是已经确认的非零前缀。
```

因此，只有发现一个新的非零元素，并把它放进该前缀后，`slow` 才能前进：

```python
slow = 0
for fast in range(len(nums)):
    if nums[fast] != 0:
        nums[slow], nums[fast] = nums[fast], nums[slow]
        slow += 1
```

`slow += 1` 不能无条件执行，否则 `[0, slow)` 可能包含零，不变量被破坏。

#### 3. 对撞双指针：应该移动哪一端？

以有序数组找目标和为例，先决定：

```text
不变量：所有尚未排除的可行配对都位于 [left, right] 内。
```

于是每次操作必须能排除一整类不可能的配对：

```python
while left < right:
    total = nums[left] + nums[right]
    if total < target:
        left += 1
    elif total > target:
        right -= 1
    else:
        return left, right
```

和太小时移动 `right` 无法得到更大的和，也无法证明被跳过候选无解；单调性迫使我们移动 `left`。

#### 4. 滑动窗口：什么时候更新答案？

求最长合法窗口时，先决定：

```text
不变量：每次更新答案时，[left, right] 必须合法。
```

代码自然变成：

```python
for right, x in enumerate(nums):
    add(x)

    while window_is_invalid():
        remove(nums[left])
        left += 1

    answer = max(answer, right - left + 1)
```

因此“求最长”通常在修复合法性后更新答案。若求最短满足条件的窗口，则应在窗口仍满足条件时先记录答案，再收缩：

```python
for right, x in enumerate(nums):
    add(x)

    while window_is_valid():
        answer = min(answer, right - left + 1)
        remove(nums[left])
        left += 1
```

#### 5. 前缀和 + 哈希：为什么先查询再计数？

以 Subarray Sum Equals K 为例：

```text
不变量：查询当前前缀和 cur 时，seen 只统计它之前的前缀和。
```

因此代码顺序是：先形成当前前缀、用旧前缀查询答案，再记录当前前缀。

```python
seen = {0: 1}
cur = answer = 0

for x in nums:
    cur += x
    answer += seen.get(cur - k, 0)
    seen[cur] = seen.get(cur, 0) + 1
```

初始的 `{0: 1}` 也由不变量推出：扫描任何元素之前，空前缀已经出现一次。

#### 6. 二分查找：边界为什么这样更新？

找第一个满足 `check(x)` 的位置时，先决定：

```text
不变量：lo 左侧全部不满足，hi 及其右侧全部满足，答案边界夹在 lo 与 hi 之间。
```

于是：

```python
while lo < hi:
    mid = (lo + hi) // 2
    if check(mid):
        hi = mid       # mid 仍可能是第一个 True，不能丢
    else:
        lo = mid + 1   # mid 已证明不是答案
return lo
```

`hi = mid` 与 `lo = mid + 1` 不是模板记忆，而是由“哪些位置已经被证明”推出来的。

#### 7. 单调栈：为什么要先弹栈再入栈？

以 Daily Temperatures 为例：

```text
不变量：栈内温度单调不增，且栈中下标都还没有找到右侧第一个更高温度。
```

新温度到来时，它可能破坏单调性，所以必须先修复：

```python
for i, temperature in enumerate(temperatures):
    while stack and temperatures[stack[-1]] < temperature:
        j = stack.pop()
        answer[j] = i - j

    stack.append(i)
```

被弹出的下标第一次遇到更高温度，可以当场结算；等所有冲突都消失后，当前下标才能安全入栈。

#### 8. 堆：为什么堆超过 K 才弹出？

求前 K 大时，先决定：

```text
不变量：处理完一个扫描前缀后，小根堆保存这个前缀最大的 K 个元素。
```

接收新元素后，暂时可能有 `K + 1` 个候选；删除其中最小者便恢复不变量：

```python
for x in nums:
    heappush(heap, x)
    if len(heap) > k:
        heappop(heap)
```

所以操作顺序是“先让新元素参与竞争，再淘汰最弱者”，不能因为新元素看起来小就随意跳过证明。

#### 9. 链表反转：为什么必须先保存 next？

先决定：

```text
不变量：prev 是已反转前缀，cur 是未处理后缀的入口，两部分合起来仍覆盖原链表全部节点。
```

修改 `cur.next` 会切断通往后缀的唯一连接，所以代码顺序被迫是：

```python
while cur:
    nxt = cur.next
    cur.next = prev
    prev = cur
    cur = nxt
```

先保存后继不是编码技巧，而是维持“节点不丢失”不变量的必要条件。

#### 10. 树的后序 DFS：返回值决定代码形状

求最大深度时，先定义递归契约：

```text
不变量/契约：dfs(node) 返回以 node 为根的子树最大深度。
```

要得到当前子树的答案，必须先得到左右子树的答案，因此自然生成后序结构：

```python
def dfs(node):
    if not node:
        return 0

    left = dfs(node.left)
    right = dfs(node.right)
    return 1 + max(left, right)
```

不是因为“树题要递归”，而是当前节点的返回值依赖子树返回值，所以递归调用必须在合并之前。

#### 11. BFS：为什么在入队时标记 visited？

先决定：

```text
不变量：队列中的每个节点都已经被发现，并且每个节点最多进入队列一次。
```

因此邻居一旦入队，就必须立刻标记：

```python
queue = deque([start])
visited = {start}

while queue:
    node = queue.popleft()
    for neighbor in graph[node]:
        if neighbor not in visited:
            visited.add(neighbor)
            queue.append(neighbor)
```

若等到出队时才标记，同一节点可能在出队前被多个父节点重复加入，不变量失效。

#### 12. 拓扑排序：为什么只有入度 0 才能入队？

先决定：

```text
不变量：indegree[v] 是 v 尚未处理的前置条件数；队列只包含当前所有前置条件均已满足的节点。
```

于是代码只能在删除一条依赖边后检查入度：

```python
queue = deque(v for v in nodes if indegree[v] == 0)

while queue:
    node = queue.popleft()
    order.append(node)

    for neighbor in graph[node]:
        indegree[neighbor] -= 1
        if indegree[neighbor] == 0:
            queue.append(neighbor)
```

入度仍大于 0 就提前入队，会让输出顺序违反依赖关系。

#### 13. 并查集：find 和 union 为什么这样分工？

先决定：

```text
不变量：同一连通分量内的所有节点，通过 parent 链最终到达同一个代表元。
```

那么查询必须先追到代表元，合并必须连接两个代表元，而不是随便连接原节点：

```python
def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])
    return parent[x]

def union(a, b):
    root_a = find(a)
    root_b = find(b)
    if root_a == root_b:
        return False
    parent[root_b] = root_a
    return True
```

路径压缩改变中间父指针，但不改变最终代表元，所以不会破坏连通关系不变量。

#### 14. Dijkstra：为什么弹出后还要检查过期距离？

先决定：

```text
不变量：从堆中弹出的、等于 dist[node] 的最小距离才是当前有效候选；在非负边权下，它可以被最终确定。
```

同一节点可能以不同距离多次入堆，所以代码自然需要：

```python
while heap:
    distance, node = heappop(heap)
    if distance != dist[node]:
        continue

    for neighbor, weight in graph[node]:
        candidate = distance + weight
        if candidate < dist[neighbor]:
            dist[neighbor] = candidate
            heappush(heap, (candidate, neighbor))
```

只有未过期状态才能扩展，否则虽然可能仍正确，却会进行大量无效工作。

#### 15. 回溯：为什么必须撤销选择？

以排列为例，先决定：

```text
不变量：进入 dfs 时，path 和 used 精确描述从根到当前搜索节点的选择。
```

每个子分支都必须从相同父状态出发，因此生成固定的“选择—递归—撤销”结构：

```python
def dfs():
    if len(path) == len(nums):
        answer.append(path.copy())
        return

    for i, x in enumerate(nums):
        if i in used:
            continue

        path.append(x)
        used.add(i)
        dfs()
        used.remove(i)
        path.pop()
```

没有撤销，兄弟分支看到的就不是父状态，不变量立即失效。

#### 16. 动态规划：遍历顺序从依赖关系产生

以 0/1 背包为例，先决定：

```text
不变量：处理完前 i 个物品后，dp[s] 表示只使用这 i 个物品能否组成 s；每个物品最多使用一次。
```

为了让当前物品不在同一轮被重复读取，容量必须倒序：

```python
dp[0] = True

for x in nums:
    for s in range(target, x - 1, -1):
        dp[s] = dp[s] or dp[s - x]
```

如果正序更新，刚写出的 `dp[s]` 可能在同一轮被再次使用，相当于允许当前物品无限次，不变量被改成了完全背包。

#### 17. 贪心：保留什么，丢弃什么？

以 Jump Game 为例，先决定：

```text
不变量：farthest 是所有已到达位置能够共同延伸出的最远边界，[0, farthest] 都可达。
```

代码只需要维护这个支配所有历史路径的边界：

```python
farthest = 0
for i, jump in enumerate(nums):
    if i > farthest:
        return False
    farthest = max(farthest, i + jump)
return True
```

无需保存“如何到达 i”的具体路径，因为对于未来而言，到达方式已被最远边界完全概括。

#### 18. 区间合并：为什么只比较最后一个结果？

先按起点排序，再决定：

```text
不变量：结果中除最后一个区间外都已经永久封口；最后一个是唯一可能继续延伸的区间。
```

于是新区间只需要和最后一个比较：

```python
intervals.sort()
merged = []

for start, end in intervals:
    if not merged or start > merged[-1][1]:
        merged.append([start, end])
    else:
        merged[-1][1] = max(merged[-1][1], end)
```

排序保证新区间的起点不会回到更早位置，因此已经封口的区间永远不需要重新检查。

#### 19. Trie：节点应该表示什么？

先决定：

```text
不变量：走完字符 s[0:i] 后，当前节点唯一代表这个前缀。
```

于是插入操作必须逐字符沿边前进，缺边才创建：

```python
node = root
for char in word:
    if char not in node.children:
        node.children[char] = TrieNode()
    node = node.children[char]
node.is_end = True
```

`is_end` 也由不变量需求产生：同一节点既可能是完整单词，也可能只是更长单词的前缀。

#### 20. 矩阵模拟：为什么走完一边立刻收边界？

以螺旋遍历为例，先决定：

```text
不变量：top、bottom、left、right 包围全部尚未访问的格子，边界外已经处理完。
```

因此每处理完一条边，就必须立即把它移出未处理矩形：

```text
遍历 top 行    → top += 1
遍历 right 列  → right -= 1
若仍有行，遍历 bottom 行 → bottom -= 1
若仍有列，遍历 left 列   → left += 1
```

后两次遍历前重新检查边界，是为了避免单行或单列矩阵被重复访问。

#### 21. 数据结构设计：多份状态如何保持一致？

以 LRU Cache 为例，先决定：

```text
不变量：哈希表与双向链表表示同一组节点；链表顺序就是使用新旧顺序。
```

因此每个公开操作都必须是一组同步更新：

```text
get(key)：哈希找到节点 → 从原位置摘除 → 移到链表头
put(key)：更新或创建节点 → 移到链表头
超容量：删除链表尾节点 → 同时删除对应哈希键
```

只更新其中一种结构，会产生幽灵节点、错误淘汰或重复节点。

#### 一条通用生成公式

遇到新题时，可以直接填写：

```text
在 ______ 时刻，我要求 ______ 始终成立。
加入/处理 ______ 会暂时破坏它。
所以必须先执行 ______，直到不变量恢复。
恢复后，我可以安全地 ______。
```

例如单调栈：

```text
在每轮结束时，我要求栈内温度单调不增。
加入更高温度会破坏它。
所以必须先弹出所有更低温度，并结算它们。
恢复后，当前下标才能安全入栈。
```

## 6. 代码前的 30 秒检查

```text
[ ] 函数在空输入、单元素、无解时返回什么？
[ ] 重复值和相等条件用 < 还是 <=？

[ ] 是否需要保留原始下标，因而不能直接排序？

[ ] 递归是否可能爆栈？
[ ] 数值和乘积是否可能溢出？
[ ] 复杂度是否满足输入规模？
```

## 7. 写完后不要只跑样例

用这五类测试攻击自己的算法：

1. 最小输入：空、一个元素。
2. 极端输入：全相同、全递增、全递减。
3. 边界答案：答案在开头、结尾、不存在、覆盖全部输入。
4. 破坏性输入：重复值、负数、零、断开的图、环。
5. 最小反例：专门挑战你移动指针、弹栈、剪枝或状态转移的理由。

手动追踪时记录“状态变化”，不要只盯最终答案：

```text
当前位置 | 数据结构内容 | 不变量是否成立 | 为什么移动/弹出/更新
```

## 8. 卡住时的救援顺序

不要随机换模板。按以下顺序退一级：

1. **重新表述**：我到底在枚举什么？
2. **缩小例子**：长度 3–5 时，人工答案是怎么得到的？
3. **写暴力**：哪一层最贵？
4. **找重复信息**：如果把它缓存，key 和 value 分别是什么？
5. **找可淘汰候选**：排序或移动边界后，哪些候选永远不用再看？
6. **找状态**：未来做决定真正需要记住哪些历史？
7. **检查单调性**：输入、窗口合法性、答案可行性是否单调？
8. **检查图模型**：元素能否看作节点，关系能否看作边？

超过 15 分钟还没有方向时，先只索取下一层提示：小例子 → 结构观察 → 不变量/数据结构 → 伪代码。不要直接背完整代码。
