# 栈与单调结构：保存尚未完成的上下文或候选

## 什么时候用

触发信号（看到任一条就该想到它）：

- 需要匹配括号、恢复嵌套上下文、执行逆波兰表达式或维护历史最小值。
- 题面出现 **"下一个更大 / 下一个更小 / 左边第一个比它矮"** 这类措辞。
- 某个元素的**作用范围**被"左右第一个更大（更小）的元素"**界定**——即"我能扩展到哪里"由邻近的破坏者决定。
- 需要对每个元素求 `L[i]` / `R[i]`（左右第一个更小/更大的下标），且暴力两边扫是 O(n²)。

**先有问题的形状，再有数据结构**：先确定"枚举以谁为高/为最小值"，发现需要 next smaller，才轮到单调栈登场。

普通栈的不变量是：栈内元素按进入顺序保存尚未闭合或尚未执行的上下文，栈顶是下一个必须处理的对象。单调栈进一步删除了未来不可能再成为答案的候选。

## 核心不变量

栈内**下标**对应的高度保持单调（递增或递减）。当前元素 `i` 打破单调性时，**栈顶元素当场结算**，此刻三件事同时已知：

- `R = i` —— 右边第一个破坏者，就是当前元素。
- `h = heights[stack.pop()]` —— 被结算者本身。
- `L = stack[-1]`（弹出后的新栈顶）—— **左边第一个更小的**。

**为什么新栈顶就是 L**：栈内单调递增 ⇒ 新栈顶必比被弹出者矮；而原本夹在两者之间的柱子早已被弹掉（它们都不比被弹出者矮）⇒ 中间没有漏网之鱼。这段论证要能脱口而出。

## 紧凑模板

```python
stack = []          # 存【下标】，永远存下标：宽度只能靠下标算，高度随时 heights[i] 查回来
best = 0
for i, h in enumerate(heights):
    while stack and heights[stack[-1]] > h:     # 打破单调 ⇒ 结算栈顶
        height = heights[stack.pop()]
        L = stack[-1] if stack else -1          # 栈空 ⇒ 左边没有更矮的，哨兵 -1
        best = max(best, height * (i - L - 1))  # 宽度 = R - L - 1
    stack.append(i)

while stack:                                    # 收尾 flush：剩余元素右边没有更矮的，R = n
    height = heights[stack.pop()]
    L = stack[-1] if stack else -1
    best = max(best, height * (len(heights) - L - 1))
```

**哨兵替代方案**：在 `heights` 末尾追加一个 `0`，强制清空栈，可省掉整段 flush（代码短一半）。

## 常见错误

- **宽度写成 `R - L`**（`off-by-one`）：`L` 和 `R` 是**两堵墙**，本身不属于矩形，可用区间是 `[L+1, R-1]` ⇒ 宽度 `R - L - 1`。反例 `[2,1,2]` 中间那根：`L=-1, R=3`，正确宽度 3，写成 `R-L` 会得 4（比数组还长）。**记忆锚点：两堵墙之间的空地，墙不算数。**
- **栈空时 L 取 0**：必须取 **-1**。取 0 会让最左侧的矩形宽度少 1。
- **忘记收尾 flush**：单调递增数组（如 `[1,2,3,4,5]`）全程不触发 while，答案 100% 依赖 flush。必须有这个测试用例。
- **`>` vs `>=` 说不清**（面试分水岭）：两者都能 AC，但**理由不同**。用严格 `>` 时，等高元素不弹出，被留下者算出的 `L` 是一根**等高**柱子而非"严格更矮"⇒ **宽度偏小、该格算错**。最终答案仍对，是因为等高串里**最左那根总能拿到完整宽度**，配合 `max` 把偏小的盖过去。走一遍 `[3,3]`：弹 idx1 得 3（错），弹 idx0 得 6（对）。能主动讲出这点 = 真懂；只会说"都能过" = 背模板。

## 与相邻模式的对比（决策边界）

- **42 接雨水**：单调栈同样"遇到破坏者就结算栈顶"，但结算的是**横向水条**（弹出者为底，`min(新柱, 新栈顶)` 为顶），84 结算的是**矩形**。两题是同一招的两种收割方式。
  - 42 也可用**双指针 O(1) 空间**（逐列结算），84 不行——84 必须知道左右第一个更矮的**下标**来算宽度，双指针给不出。
- **对撞双指针**（11 盛水）：靠支配论证**丢弃**候选，适用于**求最值**；单调栈是**逐个结算**，适用于"每个元素都有独立贡献"的场景。参见 [[two-pointers]] 中的"求最值 vs 求和"分水岭。
